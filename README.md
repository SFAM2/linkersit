# LinkersIT

Next.js website for Vercel, with a server-side Resend contact form and Google reCAPTCHA v2.

## Run locally

Use Node.js 22 or newer. Run `npm ci`, copy `.env.example` to `.env.local`, add local values, and run `npm run dev`.
Run `npm test` for the contact-handler checks, and `npm run build` followed by `npm start` for a production preview.

## Deploy on Vercel

1. Import **SFAM2/linkersit**, branch **main**, in Vercel. Use the Next.js framework preset and repository root. Leave build/output settings at their Next.js defaults.
2. Add the environment variables below in Vercel project settings. Redeploy after changing them.
3. Verify `linkersit.com` in Resend using its DNS records. Use a sending API key restricted to the verified domain where possible.
4. Add production hostnames to the reCAPTCHA v2 checkbox key's allowed domains. For previews, register the specific preview hostname and include it in `RECAPTCHA_ALLOWED_HOSTS`; do not allow all of `vercel.app`. Use a separate localhost key for development.
5. Add `linkersit.com` / `www.linkersit.com` to Vercel and follow its DNS instructions. The website is served at `/`; old `/new/` and `.html` URLs redirect to their equivalents.
6. Submit a real enquiry after deployment and verify receipt at `contact@linkersit.com`. The API reports provider acceptance, not guaranteed inbox delivery.

| Variable | Value |
| --- | --- |
| `SITE_URL` | `https://linkersit.com` (or the intended canonical origin) |
| `RESEND_API_KEY` | Your private Resend sending API key |
| `CONTACT_FROM_EMAIL` | An address on your Resend-verified domain, e.g. `contact@linkersit.com` |
| `RECAPTCHA_SITE_KEY` | Public v2 checkbox site key |
| `RECAPTCHA_SECRET_KEY` | Matching private verification key |
| `RECAPTCHA_ALLOWED_HOSTS` | Exact comma-separated hostnames, e.g. `linkersit.com,www.linkersit.com` |

No secret has a `NEXT_PUBLIC_` prefix. Missing settings fail closed. The site renders without credentials; email submission requires all form variables.

The recipient is fixed server-side to `contact@linkersit.com`. Visitor addresses are used only for Reply-To. The endpoint validates size and fields, requires a signed cookie/CSRF token and server-verified reCAPTCHA, enforces a submission limit, and uses Resend idempotency keys to prevent duplicate emails on retries. No enquiry database is created.

For a shared five-attempts-per-hour limit across Vercel instances, configure `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN` from a private Upstash Redis database. Without them, the counter is best-effort per function instance and resets on cold starts; reCAPTCHA remains mandatory. Shared-limit connection failures reject submissions. Vercel firewall rules can provide additional request-level protection.

## Preserving the original website

All seven pages are statically rendered by Next.js from trusted, repository-owned HTML in `content/pages/`. This preserves the approved markup instead of reconstructing its layout. Metadata is in `content/metadata.json`. Original styles, local fonts, icons, Three.js and GSAP live in `public/`. No remote HTML or visitor-supplied markup is rendered.

Navigation uses normal anchors/full document navigation so the original animation and form lifecycle remains intact. Routes: `/`, `/about`, `/privacy`, `/cookies`, `/terms`, `/legal`, plus the custom 404. Robots, sitemap, canonical URLs and structured data are generated by Next.js.

Before/after comparisons matched at 390px and 1440px across all seven pages, with motion frozen for deterministic screenshots. Subsequent privacy, cookies and legal copy updates describe Vercel, Resend and the cookie lifetime; their design is unchanged.

The legal entity details already awaiting confirmation still need the owner's review. No company identity or legal assurances have been invented.

PHP files, private upload ZIPs, credentials, original source bundles, screenshots and build output are excluded from Git. Do not deploy the old PHP packages to Vercel. Asset licence notices are retained.
